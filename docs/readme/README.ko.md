# mu

mu는 판정 커널을 갖춘 코딩 에이전트예요. pi를 깊이 고쳐 만든 포크, Jev라는 판정 레이어, 그리고 데스크톱 앱으로 이루어져 있어요.

- **mu**: 명령줄에서 쓰는 코딩 에이전트예요. pi가 할 수 있는 모든 것에 Jev의 판정 레이어를 더했어요.
- **mu 데스크톱**: mu가 들어 있는 네이티브 데스크톱 앱이에요. 내려받아서 바로 쓰면 돼요.
- **Jev**: 100밀리초 안팎으로 답하는 작은 판정 모델이에요. 일은 큰 모델이 하고, Jev는 판정 지점마다 "지금 무엇이 필요한가"라는 한 가지 질문에 답해요.

> 아직 초기 개발 단계예요. 만든 사람들은 매일 쓰고 있지만, 정식으로 릴리스한 적은 없어요. 이름, 설정, 파일 형식은 앞으로 바뀔 수 있어요.

## 설치

**데스크톱 앱.** 설치 파일은 GitHub Actions에서 빌드해 [Releases](https://github.com/qybaihe/mu/releases)에 올려요. macOS(Apple 실리콘 / Intel), Windows(x64 / Arm), Linux(x64 / Arm)를 지원해요. 앱에 런타임과 mu 본체가 들어 있어서 Node를 설치할 필요도, 따로 설정할 것도 없어요. 앱을 열고 모델(API 키 또는 구독 로그인)과 Jev 키를 연결하면 바로 시작할 수 있어요.

## Jev는 어디에 있나

Jev가 있다는 걸 느낄 일은 없어요. 모델 대신 여러분에게 질문을 하나 더 하지도 않고, 화면에 버튼을 하나 더 달지도 않아요. 바꾸는 것은 모델이 다음에 무엇을 할지뿐이에요. 턴마다 Jev는 이런 곳에 있어요.

- **말을 걸 때.** 일을 시작하기 전에, 이 메시지가 새 작업인지, 이어지는 질문인지, 정정인지 가려요. 에이전트가 일하는 중에 한마디 끼어들면, 하던 일을 멈출지 정해요.
- **손대기 전에.** 이 명령이 되돌릴 수 없는 결과를 낳을지, 여러분이 정한 규칙대로라면 통과시켜도 되는지 판단해요. 권한 모드가 'Jev 승인'일 때는 물어봐야 할 것만 묻고, 나머지는 바로 통과시켜요.
- **도구가 결과를 돌려줄 때.** 출력에서 무엇을 컨텍스트에 넣고 무엇이 반복과 노이즈인지 가려요. 테스트 로그에서는 실패한 부분은 남기고 거듭 반복되는 부분은 걷어 내요. 오래된 결과는 내려놓아요.
- **컨텍스트가 길어질 때.** 요약을 쓰지 않고도 내려놓을 수 있는 것이 무엇인지, 곧 만료될 캐시를 한 번 더 연장할 만한지 판단해요. 캐시 적중률이 높고 컨텍스트가 가득 차지 않는 이유가 여기에 있어요.
- **턴이 끝날 때.** 일이 끝났는지는 큰 모델이 확인하고, Jev가 폴백을 맡아요. 에이전트가 작업에서 벗어나지 않았는지, 체크포인트로 되돌아가야 할지도 판단해요.
- **배울 때.** 여러분의 정정, 에이전트가 스스로 피해 간 함정, 서브 에이전트가 가져온 교훈을 두고, 남길 만한지, 기존 교훈과 같은지 아니면 모순되는지, 이번에 지켜졌는지 판단해요. 아무도 따르지 않는 교훈은 저절로 사용이 중지돼요.
- **에이전트가 여럿일 때.** 작업을 어떤 역할에 맡길지, 서브 에이전트가 돌려준 패치가 선을 넘지 않았는지, 하이브에서 어떤 발견을 다른 비(bee)에게 넘길 만한지 판단해요.

판정 지점은 서른 개가 넘어요. 지점마다 설정에서 Jev, 로컬 판정(Laya: 여러분의 컴퓨터에서 돌아가고 네트워크에는 전혀 닿지 않는 모델), 끄기 가운데 하나를 따로 고를 수 있어요. 모든 판정은 판정 기록에 남고, 데스크톱 앱의 오른쪽 패널에서 볼 수 있어요.

## 하이브

멀티 에이전트 시스템은 모두 같은 질문에 답해야 해요. 한 에이전트가 아는 것을 다른 에이전트에게 알려야 할까요? 흔한 답은 네 가지예요. 아무것도 넘기지 않고 메인 에이전트에게만 보고하기, 그룹 채팅이나 인수인계 때 전체 기록을 통째로 넘기기, 각 에이전트의 큰 모델이 스스로 정하게 하기, 아니면 고정된 규칙과 환경(구독, git)에 기대기. mu의 답은 다섯 번째예요. Jev를 문지기로 세우는 거예요.

하이브는 비 2마리에서 6마리로 이루어지고, 비마다 자기 관심사가 있어요. 비는 코드를 읽고, 명령을 실행하고, 브라우저를 써요. 코드를 고치지는 않고, 변경은 메인 모델이 해요. 비가 말을 한 차례 마칠 때마다 Jev가 한 번 판정해요. 여기에 공유할 만한 것이 있는지, 있다면 발견인지, 막다른 길인지, 결정인지, 블로커인지를요. 공유할 만한 것은 공유 보드에 올라가요. 보드에 새 메모가 올라올 때마다 Jev는 다른 비 하나하나에 대해 한 번 더 판정해요. 이 메모가 그 비의 관심사와 관련이 있는지를요. 관련이 있으면 "지시가 아니라 발견"이라고 표시해서 그 비에게 전달해요.

보드는 쌓이기만 하고 지워지지 않아서, 나중 결론이 앞선 결론을 뒤집을 수 있어요. 어떤 비가 처음에는 테스트가 안 돌아간다고 했다가, 환경 변수 하나를 지우고 나서 돌아가게 만드는 식이에요. Jev는 두 메모의 관계(뒤집음, 모순, 뒷받침)를 판정해요. 뒤집힌 결론은 '정정'이 되어 옛 결론을 가진 모든 비에게 전달돼요. 서로 모순되는 두 메모는 둘 다 남고 '이견'으로 표시되며, 1분 안에 아무도 결론을 내지 않으면 검증 비를 보내 확인해요.

<p align="center"><img src="swarm.png" width="960" alt="데스크톱 앱의 하이브 탭: 비 네 마리가 각각 무엇을 하는지, 비들 사이의 연결 지도, 전달된 메시지 하나하나의 원문"></p>

이 모든 일이 벌어지는 현장이 데스크톱 앱 오른쪽의 하이브 탭이에요. 비마다 한 줄씩 역할, 모델, 지금 하는 일이나 방금 한 말을 보여 줘요. 지도에는 누가 누구에게 발견을 전달했는지가 그려져요. 전달이 많을수록 선이 굵고, 정정과 이견은 각자 따로 표시돼요. 발견이 도착하는 순간 그 선이 한 번 빛나요. 정보 흐름에는 전달된 메시지의 원문이 모두 있고, 판정 기록에는 Jev가 내린 판정이 모두 있어요. 대화 안의 하이브 카드에는 작은 지도가 들어 있고, 누르면 이 탭이 열려요.

실제 실행 한 번을 예로 들면, 비 3마리가 9분 동안 일하는 사이 Jev가 후보 117개를 판정했고, 27개가 보드에 올라갔고, 16개가 그것을 필요로 하는 비에게 전달됐어요. 모든 판정은 실행 디렉터리의 로그에 기록되어 나중에 되짚어 볼 수 있어요.

`/swarm`은 비마다 지금 무엇을 하는지 보여 주고, `/swarm stop`은 지금 바로 보고하게 하고, `/swarm kill`은 즉시 끝내요. 시간이 다 된 비에게는 보고를 요청하고, 보고가 없으면 끝내요. 멈춰 버린 모델이나 도구는 워치독이 처리해요. 하이브는 언제나 돌아와요.

## 쉬운 말 보드

코드를 읽지 않는 사람도 에이전트가 어디까지 했는지 알 수 있어요. 보드를 켜면(`/board`, 또는 데스크톱 앱 보드 탭 맨 위의 스위치), 에이전트가 몇 단계씩 진행할 때마다 보드가 쉬운 말로 세 가지를 알려 줘요. 지금 무엇을 하고 있는지, 체크리스트 항목 중 몇 개가 끝났는지, 확인이 필요한 것은 무엇인지요. 그 아래에는 이전 업데이트가 모두 순서대로 남아 있어요. 실행이 끝나면 보드가 전체를 요약해요.

<p align="center"><img src="board.png" width="960" alt="데스크톱 앱의 쉬운 말 보드: 일이 어디까지 진행됐는지, 지금 무엇을 하는지, 그전에 무슨 일이 있었는지. 맨 위에는 컨텍스트 사용량과 캐시 적중률"></p>

이 글은 모델이 한 말을 줄인 것이 아니에요. Jev가 판정과 이벤트 가운데 정말 새 소식이라 할 만한 몇 가지를 고르고, 설명을 잘하는 모델이 그것을 전해요. 보드는 권한 모드, 목표, 서브 에이전트를 따라가고, 에이전트가 방식을 바꾸면 보드가 전하는 말도 달라져요. 맨 위의 두 숫자는 컨텍스트를 얼마나 쓰고 있는지와 캐시 적중률이에요. Jev가 컨텍스트와 캐시에 대해 내린 판정의 결과이고, 이번 턴을 얼마나 더 이어 갈 수 있을지 가늠하는 기준이기도 해요.

## 그 밖에도

- **세 가지 권한 모드.** 전체 접근, Jev 승인, 최소 권한 중에서 고르고, 입력창에서 언제든 바꿀 수 있어요.
- **목표.** `/goal <조건>`을 쓰면 조건이 충족될 때까지 에이전트가 계속 일해요. `/goal clear`로 끝내요.
- **교훈.** 지우지 않고 쌓아 가며, 고칠 수도 있고 사용을 중지할 수도 있어요. 명령줄과 데스크톱 앱이 함께 써요.
- **구독 로그인.** ChatGPT, Claude, Grok, 그리고 Gemini CLI / Antigravity용 Google 로그인을 앱 안에서 할 수 있어요.
- **가져올 수 있는 대화.** Claude Code와 Codex CLI의 대화를 가져와서 이어 갈 수 있어요.
- **내장 브라우저, 백그라운드 작업, MCP.** 에이전트가 브라우저를 한 단계씩 조작해요. 개발 서버와 오래 걸리는 빌드는 백그라운드에서 돌려요. MCP 서버는 필요할 때 시작돼요.

## 명령어

입력창에 `/`를 치면 불러올 수 있어요. 데스크톱 앱에서는 명령어 팔레트(⌘K)에서도 찾을 수 있어요.

| 명령어 | 하는 일 |
| --- | --- |
| `/goal <조건>` | 조건이 충족될 때까지 계속 작업하기 |
| `/permissions` | 전체 접근 / Jev 승인 / 최소 권한 |
| `/board` | 쉬운 말 보드 켜고 끄기 |
| `/remember`, `/lessons`, `/forget` | 교훈 하나 남기기, 교훈 목록 보기, 하나 사용 중지하기 |
| `/review`, `/commit` | 변경 사항을 리뷰하고 지적 사항을 심각도별로 나누기, 커밋 작성하기 |
| `/checkpoints`, `/rewind` | 체크포인트 목록 보기, 그중 하나로 되돌아가기 |
| `/agents`, `/swarm` | 서브 에이전트 보내기, 일하는 비를 하나하나 지켜보기 |
| `/browse`, `/jobs` | 내장 브라우저, 백그라운드 작업 |
| `/import-chat` | Claude Code 또는 Codex 대화 가져오기 |
| `/doctor` | 설정과 연결 점검하기 |

## 프라이버시

키는 이 컴퓨터의 `~/.mu`에만 저장돼요. mu는 모델이나 런타임을 대신 내려받지 않아요. 내려받아야 하는 것은 모두 먼저 물어봐요. Jev는 판정에 필요한 조각만 봐요.

## 개발

```bash
npm install --ignore-scripts   # 의존성 설치, 라이프사이클 스크립트는 실행하지 않음
npm run check                  # 포맷, 린트, 타입 검사
./test.sh                      # 테스트 (모델이 필요한 테스트는 키가 없으면 건너뜀)
```

데스크톱 앱은 `desktop/`에 있어요. `bun install` 다음에 `KYRN_ROOT="$(cd .. && pwd)" bun run start`를 실행하면 이 저장소의 mu를 쓰는 개발 빌드가 시작돼요(먼저 루트에서 `npm install`을 실행하세요). 저장소 구조와 기여 규칙은 [AGENTS.md](../../AGENTS.md)에 있어요.

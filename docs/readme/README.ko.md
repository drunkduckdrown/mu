> **상태: 초기 개발 단계.** mu는 제작자들의 일상 작업에서는 잘 동작하지만, 아직 릴리스된 것은 없습니다. 이름, 설정, 파일 형식은 아직 바뀔 수 있습니다. *실험적*으로 표시된 기능은 실제 계정이나 모든 종류의 실제 기기에서 아직 시험해 보지 않았습니다. 무엇이 검증되었고 무엇이 검증되지 않았는지는 문서에 정확히 적혀 있습니다.

## 왜 mu인가

코딩 에이전트는 모델 호출과 컨텍스트 윈도우의 놀라울 만큼 많은 부분을 사소한 질문에 씁니다. 이 메시지는 새 작업일까요, 아니면 수정 요청일까요? 이 명령에는 사용자의 허락이 필요할까요? 4,000줄짜리 테스트 로그에서 중요한 부분은 어디일까요? 에이전트가 같은 자리를 맴돌고 있지는 않을까요? 이 일에는 어떤 하위 에이전트와 어떤 모델이 맞을까요? 브라우저는 다음에 무엇을 클릭해야 할까요?

mu는 이런 질문을 **판정 모델**(저지)에게 넘깁니다. 판정 모델은 형식이 정해진 예/아니요 질문과 객관식 질문에 1초도 안 되는 시간 안에 답하는 빠른 모델입니다. 그 답에 따라 실제로 동작하는 것은 코드입니다. 여러분의 코드를 읽고 쓰는 메인 모델은 필요한 것만 봅니다.

- **모든 결정이 보입니다.** 결정마다 `off`, `shadow`(질문하고 기록하지만 그에 따라 행동하지는 않음), `active` 세 가지 모드 중 하나로 동작합니다. 판정 결과와 소요 시간은 원장(`/ledger`, `mu ledger`)에 기록됩니다.
- **모든 결정은 실패해도 멈추지 않습니다(fail open).** 판정 모델이 확신하지 못하거나, 느리거나, 연결되지 않으면 단순한 규칙이 결정하거나 pi의 기본 동작이 실행됩니다.
- **판정 모델은 갈아 끼울 수 있습니다.** mu는 [JeV](../../kyrn/docs/08-jev-retrospective.md)(호스팅형, Vercel AI Gateway 경유), *Laya*(macOS용 로컬 판정 모델, Core ML), 이미 사용 중인 어떤 언어 모델이든, 또는 이들 여러 개를 계층으로 묶어 사용할 수 있습니다. 계층 구성에서는 앞 단계의 판정 모델이 확신하지 못한 것만 다음 판정 모델에게 넘어갑니다.

mu는 미니멀하고 확장 가능한 터미널 코딩 에이전트인 [pi](https://github.com/earendil-works/pi)를 기반으로 합니다. pi의 코어는 거의 건드리지 않고, 판정 레이어를 확장(`packages/kyrn-judge`)으로 추가합니다. 데스크톱 앱은 [AionUi](https://github.com/iOfficeAI/AionUi)를 기반으로 합니다.

## 현재 할 수 있는 일

**판정 레이어**: 32개 기능에 걸쳐 판정 지점 29개

- **모든 메시지를 먼저 읽습니다.** 판정 모델은 이번 턴이 어떤 종류인지(새 작업, 수정 요청, 새 제약 조건, 곁가지 질문), 추론이 얼마나 필요한지, 먼저 계획을 세울지를 결정합니다. 그동안 메시지는 입력창 위에서 대기하며(`esc`를 누르면 대기를 건너뜁니다), 판정 결과는 채팅에서 메시지 아래에 남습니다.
- **작업 프레임.** mu는 목표, 반드시 지켜야 할 제약 조건(여러분이 한 말 그대로, 어디서 말했는지와 함께), 현재 하위 목표, 수락 조건 체크리스트를 관리합니다. 편집 전에 변경 사항을 제약 조건과 대조하고, 명백한 위반은 여러분의 말을 인용하며 차단합니다. `/frame`으로 확인할 수 있습니다.
- **컨텍스트를 가볍게 유지합니다.** 테스트 로그에서 반복되는 실패는 한 번만 남깁니다. 도구, MCP 서버, 언어 서버, 팩은 설치되어 있어도 작업에 필요해질 때까지 숨겨 둡니다(역량 카탈로그). 새로 생긴 컴파일러 오류만 보고합니다(기준선 대비 LSP 진단). 스킬과 교훈은 작업마다 골라 씁니다.
- **세 가지 권한 모드.** *전체 접근*, *JeV 승인*(판정 모델이 작업에 분명히 필요한 것은 승인하고 나머지는 여러분에게 묻습니다), *최소 권한*(읽기를 제외한 모든 작업에서 묻습니다) 중에서 고를 수 있습니다. `/permissions`로 전환합니다. 어떤 단계에 여러분의 승인이 필요하면 상태 표시줄에 확인 요청이 나타납니다.
- **목표 모드.** `/goal <condition>`은 조건이 충족될 때까지 에이전트가 계속 작업하게 합니다. 에이전트가 멈추려 할 때마다 언어 모델이 증거를 읽습니다. 확실한 사실이 우선합니다. 체크되지 않은 체크리스트 항목이나 아무 검증도 거치지 않은 편집이 있으면 아직 완료되지 않은 것입니다.
- **쉬운 말 보드.** 코드를 읽지 않는 사람을 위해 작업 상황을 쉬운 말로 전하는 보드(plain-language board)입니다. 몇 단계마다 판정 모델이 실제로 새 소식이라 할 만한 것을 고르고, 설명을 잘하는 모델이 이를 다시 풀어 전합니다. 작업이 얼마나 진행됐는지, 지금 무슨 일이 일어나고 있는지, 여러분이 해 줘야 할 일은 무엇인지를 알려 줍니다. 실행이 끝나면 보드가 전체를 요약합니다. 프로젝트마다 `/board on`으로 켭니다.
- **체크포인트와 되돌리기.** 각 턴의 첫 편집 전에 작업 공간을 섀도 git 디렉터리에 스냅샷으로 저장합니다. 여러분의 인덱스와 stash는 절대 건드리지 않습니다. `/rewind`는 파일, 대화 또는 둘 다를 복원합니다. 에이전트가 같은 방식으로 계속 실패하면 판정 모델이 되돌리기를 제안할 수 있지만, 스스로 되돌리지는 않습니다.

**하위 에이전트와 브라우저**

- **`delegate`.** 독립적인 부분은 병렬로, 또는 여러 단계로 이어진 체인으로 실행합니다. 파일을 편집하는 부분은 각자의 git worktree에서 작업하고 패치를 돌려줍니다. 각 하위 에이전트는 자기 체크리스트에 따라 일하고, 그 체크리스트를 채워 보고합니다. `/implement`, `/scout-and-plan`, `/implement-and-review`는 미리 만들어 둔 체인입니다.
- **`hive`.** 하나의 어려운 문제에 여러 조사 에이전트가 동시에 달라붙고, 어떤 발견 사항을 서로 주고받을지는 판정 모델이 결정합니다.
- **내장 브라우저.** `browse`는 관찰, 판정 모델 호출 한 번, 행동으로 이루어진 루프를 실행합니다. 데스크톱 앱에서는 전용 브라우저 패널에서 모든 단계를 지켜볼 수 있고, 언제든 직접 제어를 넘겨받을 수 있습니다. 되돌릴 수 없는 작업은 먼저 묻습니다.

**일상 도구**

- **이미 쓰던 설정을 그대로 가져옵니다.** mu는 Claude Code, Cursor, Codex용으로 설정해 둔 규칙, 스킬, MCP 서버를 읽습니다.
- **팩.** 발견 사항에 P0–P3 우선순위를 매기는 `/review`와, 변경 사항을 여러 커밋으로 나누되 계획부터 보여 주는 `/commit`이 있습니다. 그 밖에 ast-grep, `gh`를 통한 GitHub 연동, 충돌 해결, DAP 디버거(debugpy, delve, lldb-dap)도 있습니다.
- **백그라운드 작업, 웹 페이지 가져오기와 검색**(중국 본토에서도 쓸 수 있는 소스 포함), 그리고 Claude, ChatGPT, Grok, Google **로그인**을 지원합니다. Gemini CLI 또는 Antigravity를 통한 Google 로그인은 *실험적*이며, mu가 위험을 알리고 브라우저를 열기 전에 먼저 묻습니다.

**데스크톱 앱** (`desktop/`)

- JeV 패널이 모든 판정 결과를 보여 줍니다.
- 브라우저 패널은 mu가 조작합니다.
- 쉬운 말 보드와 권한 확인 요청을 보여 줍니다.
- 설정 화면은 판정 모델, 결정 모드, 기능, OpenAI 또는 Anthropic 호환 엔드포인트를 쓰는 프로바이더까지 하네스 자체의 매니페스트에서 생성됩니다.
- 안내에 따라 진행하는 첫 실행과 로그인.
- 13개 언어를 지원하는 인터페이스.

## 저장소 구조

| 경로 | 설명 |
| --- | --- |
| `packages/kyrn-judge` | mu 본체: 판정 커널, 판정 명세 29개, 위의 모든 기능을 담은 pi 확장 |
| `packages/*` (그 외) | pi의 모노레포: `ai`(프로바이더), `agent`(루프), `coding-agent`(CLI), `tui`, … 작은 패치 몇 개 적용 |

| `kyrn/docs` | 설계 노트, 제품 계획, 기능마다 한 편씩 있는 문서(대부분 중국어) |

*KYRN*은 이 프로젝트의 이전 이름입니다. 폴더와 패키지 이름에는 아직 이 이름이 남아 있습니다.

## 설치

```bash
npm i -g mu-agent
mu
```

Node.js 22.19 이상이 필요합니다. 패키지 이름은 `mu-agent`, 명령은 `mu`이며 macOS, Linux, Windows, WSL에서 동작합니다. `npm i -g mu-agent@latest`로 업데이트합니다. 아래 내용은 그대로 적용되며, 한 가지만 다릅니다. JeV 키는 `kyrn/.env`가 아니라 환경 변수나 `~/.mu/.env`에 넣습니다.

## 소스에서 시작하기

Node.js 22.19 이상(24 권장), npm, git이 필요합니다.

```bash
git clone https://github.com/qybaihe/mu.git
cd MU
npm install
kyrn/bin/mu            # Windows: kyrn\bin\mu.cmd
```

mu 안에서 `/login`으로 모델 프로바이더에 로그인하고 `/model`로 모델을 고릅니다. `/help`는 모든 명령을 나열하고, `/doctor`는 설정을 점검합니다. `mu`를 PATH에 추가하려면 `kyrn/bin/mu link`를 실행하세요.

**판정 모델을 고르세요.** 판정 모델이 없으면 mu는 추가 도구가 딸린 pi처럼 동작합니다.

- **JeV:** Vercel AI Gateway 키를 `kyrn/.env`에 `AI_GATEWAY_API_KEY`로 넣습니다(`kyrn/.env.example` 참고).
- **Laya(로컬, macOS 전용):** `mu judge setup`을 실행합니다. 약 930 MB를 내려받으며, 시작하기 전에 먼저 묻습니다.
- **이미 쓰고 있는 어떤 모델이든:** `/mu judge llm:<provider>/<model>`.

결정은 `shadow` 모드로 시작하므로, 판정 모델이 무엇을 할지 지켜볼 수 있습니다. 믿을 만하다고 판단되면 `/mu mode default active`를 실행하거나 `~/.mu/agent/mu.json`에 `"modes": {"default": "active"}`를 설정하세요.

**소스에서 데스크톱 앱 실행하기**([Bun](https://bun.sh) 사용):

```bash
cd desktop
bun install
KYRN_ROOT="$(cd .. && pwd)" bun run start     # Windows (PowerShell): $env:KYRN_ROOT = (Resolve-Path ..); bun run start
```

앱은 `KYRN_ROOT`가 가리키는 체크아웃에서 mu를 실행하므로, 먼저 저장소 루트에서 `npm install`을 실행하세요.

## 빌드

푸시할 때마다 GitHub Actions가 검사를 돌립니다. 널리 쓰이는 모든 플랫폼용 데스크톱 앱을 빌드하고, `v*` 태그마다 릴리스를 게시합니다.

| | x64 | arm64 |
| --- | --- | --- |
| **macOS** | `.dmg`, `.zip` (Intel) | `.dmg`, `.zip` (Apple silicon) |
| **Windows** | `.exe` 설치 프로그램 | `.exe` 설치 프로그램 |
| **Linux** | `.deb` | `.deb` |

모든 릴리스에는 저장소의 소스 아카이브도 포함됩니다.

이 빌드는 **미리보기 빌드**입니다.

- 아직 코드 서명이 되어 있지 않습니다. macOS는 처음 실행할 때 *시스템 설정 → 개인정보 보호 및 보안*에서 실행을 확인하도록 요구하고, Windows에서는 SmartScreen 경고가 표시됩니다.
- 앱에는 아직 mu가 들어 있지 않습니다. 같은 기기에 있는 이 저장소의 체크아웃에서 mu를 실행하므로, `KYRN_ROOT`를 그 체크아웃 경로로 설정하세요.

`mu` 명령줄 도구는 이 모든 플랫폼에서 npm으로 설치할 수 있고(`npm i -g mu-agent`, 위 참고), 소스에서 실행할 수도 있습니다.

## 진행 중인 작업

- **mu를 앱에 내장하고, 단독 실행 바이너리로도 제공.** 내려받은 앱은 체크아웃도 `KYRN_ROOT`도 없이 단독으로 동작해야 하고, `mu` 명령은 플랫폼마다 파일 하나로 제공되어야 합니다.
- **앱을 mu의 주된 사용 방식으로.** 전체 흐름이 터미널 브리지를 거치지 않고 데스크톱 앱 안에서 실행되도록 합니다. 이를 위해서는 순서가 보장된 하나의 이벤트 스트림으로 채워지는 네이티브 대화 화면이 필요합니다.
- **원클릭 로컬 판정 모델.** 설정에서 Laya를 설치할 수 있게 합니다. 크기와 출처를 보여 주고, 무엇이든 내려받기 전에 여러분의 동의를 구합니다.
- **실제 기기에서의 Windows와 WSL.** 코드 경로는 이미 있고 단위 테스트도 거쳤지만, 아직 실제 Windows 기기에서 확인해야 합니다.
- **판정 모델 측정.** 판정 지점마다 실제 세션에서 JeV와 Laya가 얼마나 자주 맞히는지 측정해, 임계값을 조정할 수 있게 합니다.
- **의미 드리프트 검사**(*실험적*). 판정 모델이 스트리밍되는 모델 출력을 지켜보다가, 여러분이 정한 규칙을 명백히 어길 때만 출력을 멈춥니다.

## 기여하기

먼저 [AGENTS.md](../../AGENTS.md)를 읽어 주세요. 요약하면 들여쓰기는 탭, import는 `.ts`를 붙인 상대 경로, TypeScript는 타입만 지우면 되는 문법(erasable syntax)만, 의존성 버전은 정확히 고정입니다. `npm run check`와 여러분이 건드린 테스트를 실행하세요. 전체 테스트 스위트는 오래 걸리니, 푸시할 때마다 실행되는 CI에 맡기세요. 테스트는 모의 판정 모델과 가짜 모델을 사용하며, 실제 모델을 절대 호출하지 않습니다.

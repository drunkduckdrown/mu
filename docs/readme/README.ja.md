## なぜ mu なのか

コーディングエージェントは、モデル呼び出しとコンテキストウィンドウの意外なほど大きな割合を、小さな問いに費やしています。このメッセージは新しいタスクなのか、それとも修正なのか。このコマンドにはユーザーの許可が必要か。4,000 行のテストログのどこが重要か。エージェントは同じところをぐるぐる回っていないか。この仕事にはどのサブエージェントとどのモデルが合うか。ブラウザは次に何をクリックすべきか。

mu はこうした問いを**判定モデル**（judge）に任せます。答えの型が決まった yes/no の質問や多肢選択の質問に、1 秒足らずで答える高速なモデルです。その答えに基づいて動くのはコードです。メインモデル、つまりあなたのコードを読み書きするモデルは、必要なものだけを目にします。

- **すべての判定が見える。** 判定ごとにモードがあります。`off`、`shadow`（問い合わせて記録するが、その結果では動かない）、`active` のいずれかです。判定結果と所要時間は台帳（`/ledger`、`mu ledger`）に記録されます。
- **すべての判定はフェイルオープン。** 判定モデルが確信を持てない、遅い、あるいは到達できない場合は、単純なルールが決めるか、pi の標準の動作がそのまま実行されます。
- **判定モデルは差し替え可能。** mu は [JeV](../../kyrn/docs/08-jev-retrospective.md)（ホスト型、Vercel AI Gateway 経由）、*Laya*（macOS 上のローカル判定モデル、Core ML）、すでに使っている任意の言語モデル、あるいはこれらを複数組み合わせた階層構成を使えます。階層構成では、後段の判定モデルには前段が確信を持てなかったものだけが渡されます。

mu は、ミニマルで拡張可能なターミナル型コーディングエージェント [pi](https://github.com/earendil-works/pi) をベースにしています。pi のコアにはほとんど手を加えず、判定レイヤーを拡張機能（`packages/kyrn-judge`）として追加しています。デスクトップアプリは [AionUi](https://github.com/iOfficeAI/AionUi) をベースにしています。

## 現在できること

**判定レイヤー**：32 の機能にまたがる 29 の判定ポイント

- **すべてのメッセージをまず読む。** 判定モデルは、そのターンがどんな種類か（新しいタスク、修正、新しい制約、本題とは別の質問）、どれだけの推論が必要か、先に計画を立てるべきかを判断します。その間メッセージはエディタの上で待機し（`esc` で待機をスキップ）、判定結果はチャット内でメッセージの下に残ります。
- **タスクフレーム。** mu は、ゴール、あなたが自分の言葉で述べたハード制約（どこで述べたかも含めて）、現在のサブゴール、受け入れ条件チェックリストを保持します。編集の前には、その変更が制約に照らしてチェックされ、明らかな違反はあなたの言葉を引用したうえでブロックされます。`/frame` で表示できます。
- **コンテキストを無駄なく保つ。** テストログ中で繰り返される失敗は 1 回分だけ残します。ツール、MCP サーバー、言語サーバー、パックはインストール済みでも、タスクで必要になるまでは隠しておきます（ケイパビリティカタログ）。報告されるのは新しいコンパイラエラーだけです（ベースラインと比較した LSP 診断）。スキルと教訓はタスクごとに選ばれます。
- **3 つのモードの権限管理。** *フルアクセス*、*JeV が承認*（タスクに明らかに必要なものは判定モデルが承認し、それ以外はあなたに確認します）、*最小限*（読み取り以外はすべて確認します）。`/permissions` で切り替えます。あるステップにあなたの承認が必要になると、ステータスバーに確認プロンプトが表示されます。
- **ゴールモード。** `/goal <condition>` は、条件が満たされるまでエージェントに作業を続けさせます。エージェントが停止しようとするたびに、言語モデルが根拠を読みます。確かな事実が優先されます。チェックリストに未完了の項目が残っている、あるいはまだ何のチェックも通っていない編集がある場合は、完了とはみなしません。
- **平易な言葉のボード。** コードを読まない人に向けて、作業の状況を平易な言葉で伝えるボードです。数ステップごとに判定モデルが本当に伝える価値のある新しい出来事を選び、説明の上手なモデルがそれを語り直します。伝えるのは、作業の進み具合、いま起きていること、あなたの対応を待っていることです。実行が終わると、ボードが全体をまとめます。`/board on` でプロジェクトごとに有効にできます。
- **チェックポイントと巻き戻し。** 各ターンの最初の編集の前に、ワークスペースのスナップショットがシャドウ git ディレクトリに保存されます。あなた自身の index や stash には一切触れません。`/rewind` でファイル、会話、またはその両方を復元できます。エージェントが同じ失敗を繰り返しているときは、判定モデルが巻き戻しを提案することがありますが、自分から巻き戻すことはありません。

**サブエージェントとブラウザ**

- **`delegate`。** 独立した部分は並列に、または順につながったステップのチェーンとして実行されます。編集を行う部分はそれぞれ専用の git worktree で作業し、パッチを返します。各サブエージェントは自分のチェックリストに沿って作業し、その達成状況を報告します。`/implement`、`/scout-and-plan`、`/implement-and-review` はあらかじめ用意されたチェーンです。
- **`hive`。** 1 つの難しい問題に対して複数の調査役が同時に取り組み、どの発見を互いに受け渡すかは判定モデルが決めます。
- **内蔵ブラウザ。** `browse` は「観察、判定モデルへの 1 回の問い合わせ、操作」のループを回します。デスクトップアプリでは、すべてのステップを専用のブラウザパネルで見ることができ、いつでも操作を引き継げます。取り消しのきかない操作は、必ず先に確認を求めます。

**日常的に使うツール**

- **すでに使っているものをそのまま活用。** mu は、Claude Code、Cursor、Codex 向けに設定したルール、スキル、MCP サーバーを読み込みます。
- **パック。** 指摘を P0〜P3 でランク付けする `/review`、そして変更を複数のコミットに分割し、先に計画を見せる `/commit`。ほかに ast-grep、`gh` 経由の GitHub、コンフリクト解決、DAP デバッガー（debugpy、delve、lldb-dap）もあります。
- **バックグラウンドジョブ、Web ページ取得と検索**（中国本土から利用できる情報源を含む）、そして Claude、ChatGPT、Grok、Google での**サインイン**（Gemini CLI または Antigravity 経由の Google は*実験的*です。mu はリスクを説明し、ブラウザを開く前に確認します）。

**デスクトップアプリ**（`desktop/`）

- JeV パネルにすべての判定結果を表示。
- ブラウザパネルは mu が操作。
- 平易な言葉のボードと権限の確認プロンプトを表示。
- 設定画面はハーネス自身のマニフェストから生成：判定モデル、判定モード、機能、OpenAI 互換または Anthropic 互換のエンドポイントを持つプロバイダー。
- ガイド付きの初回起動とサインイン。
- 13 言語に対応したインターフェース。

## リポジトリ構成

| パス | 内容 |
| --- | --- |
| `packages/kyrn-judge` | mu 本体：判定カーネル、29 の判定仕様、上記のすべての機能を pi 拡張機能として収録 |
| `packages/*`（その他） | pi のモノレポ：`ai`（プロバイダー）、`agent`（ループ）、`coding-agent`（CLI）、`tui`、…。いくつかの小さなパッチを適用 |

## ソースから始める

Node.js 22.19 以降（24 を推奨）、npm、git が必要です。

```bash
git clone https://github.com/qybaihe/MU.git
cd MU
npm install
kyrn/bin/mu            # Windows: kyrn\bin\mu.cmd
```

mu の中では、`/login` でモデルプロバイダーにサインインし、`/model` でモデルを選びます。`/help` ですべてを一覧表示でき、`/doctor` でセットアップを確認できます。`mu` を PATH に追加するには、`kyrn/bin/mu link` を実行します。

**判定モデルを選ぶ。** 判定モデルを設定しない場合、mu は追加のツールを備えた pi として動作します。

- **JeV：** Vercel AI Gateway のキーを `AI_GATEWAY_API_KEY` として `kyrn/.env` に設定します（`kyrn/.env.example` を参照）。
- **Laya（ローカル、macOS のみ）：** `mu judge setup` を実行します。約 930 MB をダウンロードし、開始前に確認を求めます。
- **すでに使っている任意のモデル：** `/mu judge llm:<provider>/<model>`。

判定は `shadow` モードで始まるので、判定モデルならどうするかを観察できます。信頼できると判断したら、`/mu mode default active` を実行するか、`~/.mu/agent/mu.json` に `"modes": {"default": "active"}` を設定してください。

**ソースからデスクトップアプリを起動**（[Bun](https://bun.sh) を使用）：

```bash
cd desktop
bun install
KYRN_ROOT="$(cd .. && pwd)" bun run start     # Windows (PowerShell): $env:KYRN_ROOT = (Resolve-Path ..); bun run start
```

アプリは `KYRN_ROOT` で指定したチェックアウトから mu を実行するので、先にリポジトリのルートで `npm install` を実行してください。

## ビルド

GitHub Actions がすべての push をチェックします。主要なすべてのプラットフォーム向けにデスクトップアプリをビルドし、`v*` タグごとにリリースを公開します。

| | x64 | arm64 |
| --- | --- | --- |
| **macOS** | `.dmg`、`.zip`（Intel） | `.dmg`、`.zip`（Apple silicon） |
| **Windows** | `.exe` インストーラー | `.exe` インストーラー |
| **Linux** | `.deb` | `.deb` |

各リリースには、リポジトリのソースアーカイブも含まれます。

これらは**プレビュービルド**です。

- まだコード署名されていません。macOS では初回起動時に *システム設定 → プライバシーとセキュリティ* で確認を求められ、Windows では SmartScreen が警告を表示します。
- アプリはまだ mu を内蔵していません。同じマシン上にあるこのリポジトリのチェックアウトから mu を実行するので、`KYRN_ROOT` にそのチェックアウトを設定してください。

`mu` のコマンドラインは、これらすべてのプラットフォームで、ソースから Node 上で動作します（上記参照）。

## 現在取り組んでいること

- **アプリへの mu の同梱と、スタンドアロンバイナリ。** ダウンロードしたアプリが、チェックアウトも `KYRN_ROOT` もなしに単体で動作し、`mu` コマンドもプラットフォームごとに 1 ファイルで提供されることを目指します。
- **mu を使う主な手段としてのアプリ。** 一連の流れ全体を、ターミナルのブリッジ経由ではなくデスクトップアプリの中で動かします。そのために、順序付けられた 1 本のイベントストリームを受け取るネイティブの会話ビューを用意します。
- **ワンクリックのローカル判定モデル。** 設定画面から Laya をインストールできるようにします。サイズと入手元を表示し、何かをダウンロードする前にあなたの同意を求めます。
- **実機での Windows と WSL。** コードパスは存在し、ユニットテストも済んでいますが、まだ実際の Windows マシンでの確認が必要です。
- **判定モデルの測定。** 判定ポイントごとに、実際のセッションで JeV と Laya がどのくらいの頻度で正しいかを測り、しきい値を調整できるようにします。
- **意味的なドリフトの検出**（*実験的*）。判定モデルがストリーミング中のモデル出力を監視し、あなたが設定したルールに明らかに反した場合にのみ停止させます。

詳細な計画と各項目のステータスは、[kyrn/docs/11-out-of-the-box-roadmap.md](../../kyrn/docs/11-out-of-the-box-roadmap.md)（中国語）にあります。

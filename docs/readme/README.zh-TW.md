# mu

mu 是一個帶判定核心的程式設計代理：pi 的一個深度分支，加上一層叫 Jev 的判定，和一個桌面版。

- **mu**：程式設計代理的命令列，pi 的全部能力，加上 Jev 的判定層
- **mu 桌面版**：原生桌面應用程式，內建 mu，下載即用
- **Jev**：一個百毫秒級的小判定模型。大模型負責做事，Jev 在每個決策點回答一個問題：現在需要什麼

> 還在早期開發階段。作者每天都在用，但還沒有正式發布過；名稱、設定和檔案格式都可能改變。

## 安裝

**桌面版。** 安裝檔由 GitHub Actions 建置，發布在 [Releases](https://github.com/qybaihe/mu/releases)：macOS（Apple 晶片 / Intel）、Windows（x64 / Arm）、Linux（x64 / Arm）。應用程式內建執行環境和 mu 本體，不需要安裝 Node，也不需要額外設定。開啟後接上一個模型（API 金鑰或訂閱登入）和 Jev 的金鑰，就能開始。

<!-- 簽署之前保留這一行；拿到憑證並完成公證後刪掉 -->
macOS 若提示無法驗證開發者：在 Finder 裡對應用程式按右鍵，選「打開」，只需要一次。

**命令列。**

```bash
npm i -g mu-agent
mu
```

需要 Node 22.19 或更新版本。桌面版和命令列共用 `~/.mu` 裡的帳號、設定和經驗。

## Jev 在哪裡

你感覺不到 Jev。它不會替模型多問你一句，也不會在介面上多加一個按鈕；它只改變模型接下來做什麼。每一輪裡，它在這些地方：

- **你說話時。** 這句話是新任務、追問還是糾正，先判斷再開工；正在做事時你插一句話，要不要打斷。
- **動手之前。** 這條指令會不會造成不可逆的後果；按你定下的規矩能不能放行；權限選「Jev 審批」時，該問你的就問你，不該問的直接放行。
- **工具回傳時。** 輸出裡哪些該進上下文，哪些是重複和雜訊；測試記錄裡失敗的部分留下，一遍遍重複的去掉；過期的結果放下。
- **上下文變長時。** 什麼可以放下而不用寫摘要；快取即將過期時值不值得續一次。這是快取命中率高、上下文一直不會滿的原因。
- **一輪結束時。** 做完了沒有，由大模型核對、Jev 作為備援；有沒有偏離任務；要不要退回某個檢查點。
- **學習時。** 你的糾正、代理自己繞過的坑、子代理帶回的教訓：值不值得記、和已有的經驗是同一條還是互相矛盾、這次有沒有照做。沒人照做的經驗會自動退役。
- **多代理時。** 交給哪種角色；子代理交回的修補檔有沒有越界；蜂群裡哪條發現值得傳給別的 bee。

三十多個決策點，每一個都能在設定裡單獨選：Jev、本機判定（Laya，模型在本機執行，不經過網路）、或關掉。每一次判定都留在判定帳本裡，桌面版的右側面板看得到。

## 蜂群

多代理系統都要回答同一個問題：一個代理知道的，要不要告訴另一個？常見的答案有四種：什麼都不傳，只向主代理回報；什麼都傳，群組聊天或交接時帶上全部歷史；讓每個代理自己的大模型決定；或者靠固定規則和環境（訂閱、git）。mu 的答案是第五種：讓 Jev 當閘門。

一個蜂群是 2 到 6 隻 bee，各有自己的關注點，只讀程式碼、執行指令、開瀏覽器；bee 不改程式碼，改動由主模型來做。每隻 bee 每說完一段，Jev 判斷一次：這段話裡有沒有值得共享的東西，是發現、死路、決定還是阻礙。值得的就放上共享板。板上每來一條新的，Jev 再對每一隻別的 bee 判斷一次：這條和它的關注點有沒有關係。有關係的就送過去，標明「這是發現，不是指令」。

板只增不刪，所以後來的結論會推翻早先的：一隻 bee 先說測試跑不起來，後來清掉一個環境變數就跑起來了。Jev 判斷兩條筆記的關係（推翻、矛盾、支持），被推翻的結論變成一條「更正」，送給所有拿著舊結論的 bee；互相矛盾的兩條都留著、標成「爭議」，超過一分鐘沒解決，就派一隻核實 bee 去查。

<p align="center"><img src="swarm.png" width="960" alt="桌面版的蜂群頁：四隻 bee 各自在做什麼，它們之間的連接圖，和每一條送達的原文"></p>

桌面版右側的「蜂群」頁就是這一切的現場。每隻 bee 一行：角色、模型、此刻在做什麼或剛說了什麼。連接圖畫出誰把發現送給了誰，線越粗代表送達越多，更正和爭議各有自己的畫法；一條發現送到的那一刻，會沿著線亮一下。資訊流裡是每一條送達的原文，判定記錄裡是 Jev 的每一次裁決。對話裡的蜂群卡片帶一張縮圖，點開就會跳到這一頁。

一次真實的執行：3 隻 bee，9 分鐘，Jev 評了 117 條候選，27 條上了板，16 條送到了需要它的 bee 那裡。每一次判定都寫在執行目錄的記錄檔裡，事後可以回頭檢視。

`/swarm` 即時看每一隻在做什麼，`/swarm stop` 讓它們現在交報告，`/swarm kill` 立刻結束。時間到了的 bee 會被要求交報告，不交的會被結束；卡住的模型或工具由看門狗處理，蜂群一定會回來。

## 人話看板

不看程式碼的人也能知道代理做到哪了。開啟看板（`/board`，或桌面版看板頁頂端的開關），代理每做一段，看板就用白話說三件事：現在在做什麼，清單上幾件事做完了幾件，有哪些要你確認；下面按時間留著之前的每一段。一次執行結束時，看板會做一次總結。

<p align="center"><img src="board.png" width="960" alt="桌面版的人話看板：進展到哪、在做什麼、之前發生了什麼；頂端是上下文用量和快取命中率"></p>

這些字不是模型原話的縮寫。Jev 從判定和事件裡挑出真正算得上新消息的那幾條，再由一個說話清楚的模型講出來；看板跟著權限、目標和子代理走，代理換了做法，看板也換一種說法。頂端兩個數字是上下文用了多少、快取命中率多少：它們是 Jev 在上下文和快取上做的那些判定的結果，也是你判斷這一輪還能走多遠的依據。

## 還有這些

- **三種權限模式。** 全部放行、Jev 審批、最小權限，隨時在傳送框切換。
- **目標。** `/goal <條件>`，代理一直做到條件成立；`/goal clear` 結束。
- **經驗庫。** 經驗只追加，可編輯，可退役；命令列和桌面版共用。
- **訂閱登入。** ChatGPT、Claude、Grok，以及 Gemini CLI / Antigravity 的 Google 登入，都在應用程式內完成。
- **帶過來的對話。** Claude Code 和 Codex CLI 的對話可以匯入，接著聊。
- **內建瀏覽器、背景指令、MCP。** 代理在瀏覽器裡一步步操作；開發伺服器和耗時的建置放到背景執行；MCP 伺服器按需啟動。

## 指令

在傳送框輸入 `/` 叫出；桌面版也能在命令面板（⌘K）裡搜尋。

| 指令 | 做什麼 |
| --- | --- |
| `/goal <條件>` | 一直做到條件成立 |
| `/permissions` | 全部放行 / Jev 審批 / 最小權限 |
| `/board` | 開啟或關閉人話看板 |
| `/remember`、`/lessons`、`/forget` | 記一條經驗、看經驗庫、讓一條退役 |
| `/review`、`/commit` | 審查變更並按嚴重程度分級；寫提交 |
| `/checkpoints`、`/rewind` | 看檢查點；退回到某一個 |
| `/agents`、`/swarm` | 派子代理；看正在工作的每一隻 |
| `/browse`、`/jobs` | 內建瀏覽器；背景指令 |
| `/import-chat` | 匯入 Claude Code 或 Codex 的對話 |
| `/doctor` | 檢查設定和連線 |

## 隱私

金鑰只儲存在本機的 `~/.mu`。mu 不會替你下載任何模型或執行環境：需要下載的東西都會先問你。Jev 只看得到判定所需的片段。

## 開發

```bash
npm install --ignore-scripts   # 安裝相依套件，不執行生命週期指令碼
npm run check                  # 格式、靜態檢查、型別
./test.sh                      # 測試（沒有金鑰時跳過需要模型的測試）
```

桌面版在 `desktop/`：`bun install`，然後 `KYRN_ROOT="$(cd .. && pwd)" bun run start` 啟動開發版，它會使用儲存庫裡的 mu（先在根目錄執行 `npm install`）。儲存庫結構、貢獻規則見 [AGENTS.md](../../AGENTS.md)。

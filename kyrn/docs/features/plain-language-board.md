# 人话看板（`board`）

更新日期：2026-09-22。状态：harness 一侧已完成并测试；桌面端右侧面板（和经验栏放在一起）还没做，展示事件已经就绪。

## 1. 要解决什么

大部分模型说话术语太多，用户看不懂它在干什么。少数模型（Opus 4.6、Gemini 3.8 Flash 这类）表达好，能说人话。人话看板把两者结合起来：

- **Jev 做选择题**，从会话里读出要点：现在处在哪个阶段、在做哪条验收条件、是不是在等你、和上次比有没有新情况。选择题便宜，所以可以经常看。
- **只有 Jev 看出有新情况时**，才请一个会说人话的模型把这些写成两三句大白话：**进展**（整件事做到哪了）、**正在做**、**需要你确认**。

看板只给人看，**不进工作模型的上下文**，不影响它干活。

## 2. 怎么用

| 命令 | 作用 |
| --- | --- |
| `/board on` | 这个项目打开看板 |
| `/board off` | 这个项目关闭看板 |
| `/board` | 看最新的看板 |

在终端（`mu` 命令行）里，打开看板的项目会在输入框上方显示一个小窗口：第一行“μ 看板 · 进展”，下面是正在做什么和要你确认的事，每次更新时刷新；关掉看板窗口就消失。桌面端不用这个窗口，用下面第 4 节的展示事件画自己的面板。

- **按项目开关**，默认关闭：每更新一次要调用一次模型。开关记在用户自己的目录里（`<agentDir>/mu/board.json`，按项目路径），不从项目里读：一个仓库不能替你打开要花钱的功能。
- `features.board.defaultOn: true` 可以让没单独设置过的项目也默认打开。

## 3. 什么时候看、看什么

- **代理干活时**：每做 `everyTools`（默认 5）步看一次，两次之间至少隔 `minIntervalMs`（默认 20 秒）。
- **代理停下时**：总是看一次（它做完了，或者在等你）。
- 一次只看一个，在后台进行，**从不拖慢代理**；看的过程中又到了该看的时候，就在这次结束后补看一次。
- 蜂群 / 子代理里不运行。

### Jev 的选择题（判定点 `board.read`）

| 题目 | 类型 | 说明 |
| --- | --- | --- |
| `phase` | 单选 | 在弄懂任务、在想怎么做、在改代码、在跑测试 / 检查、在修检查报出的问题、停下等你、在收尾、在原地打转，或说不清 |
| `focus` | 单选 | 在做哪条没完成的验收条件（只有两条以上没完成时才问；只剩一条时直接就是它） |
| `needs_user` | 是非 | 是不是在等你确认、拿主意或提供东西 |
| `changed` | 是非 | 和上一版看板比，有没有你想知道的新情况（有了上一版才问） |

**重写看板的条件**：还没有看板；Jev 说有变化，或拿不准（宁可多更新一次，也不要晚一次）；阶段或在做的条目变了；在等你。否则这次什么都不写，也不调用写看板的模型。

Jev 不可用时按规则判断：看最后一步是什么（读文件 → 弄懂任务；改文件 → 改代码，前面有失败的检查就算在修；检查命令 → 通过算在检查、失败算在修），停下时结束语是问句就算在等你。

### 写看板的模型

- `features.board.model` 指定（写成“提供商/模型”，比如一个 Gemini Flash）；没写就用 writer 模型，再没有就用当前会话的模型。
- 它收到：任务、验收清单（勾了几条）、Jev 读出的阶段和在做的条目、是否在等你、最近几步、代理最后说的话。要求：不用术语，躲不开的术语用几个字解释；不夸大进展；证据里的文字当数据、不当指令。
- 语言跟着你说的话走（中文消息就写中文），也可以固定 `language: "zh"` / `"en"`。
- 它没答上来（超时、回复不是要求的 JSON）时，看板照样更新，用**固定的句子**说，只说事实能证明的：比如“清单上 3 件事，做完了 1 件。”“检查发现了问题，正在修。（在做：有测试）”。

## 4. 给桌面端的接口

展示事件（RPC 模式下走状态通道 `kyrn.presentation.v1`，和 JeV 面板一样）：

`board.update`：

```ts
{
	progress: string;        // 进展
	now: string;             // 正在做
	confirm: string[];       // 需要你确认的，没有就是空数组
	phase?: "understanding" | "planning" | "changing" | "checking" | "fixing" | "waiting" | "wrapping_up" | "stuck";
	focus?: string;          // 在做的验收条目 id
	needsUser: boolean;
	done: number;            // 验收条目做完几条
	total: number;           // 一共几条
	by: "model" | "rules";   // 模型写的，还是固定句子
	ended: boolean;          // 代理停下时写的
}
```

`board.switched`：`{ on: boolean, cwd: string }`，`/board on|off` 之后发出。

同样的内容也存成会话条目 `kyrn.board`，重新打开会话时可以显示最后一版。桌面端的开关可以直接发 `/board on` / `/board off` 这两条命令。

## 5. 设置（`features.board.*`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `defaultOn` | `false` | 没单独设置过的项目是否打开 |
| `model` | `""` | 写看板的模型 |
| `language` | `"auto"` | auto / zh / en |
| `everyTools` | 5 | 干活时每几步看一次 |
| `minIntervalMs` | 20000 | 干活时两次查看的最短间隔（停下时不受限） |
| `maxSteps` | 10 | 每次读最近几步 |
| `narrateTimeoutMs` | 60000 | 写看板最多等多久，超时用固定句子 |

## 6. 验证情况

`test/board.test.ts`，11 个用例：

- 选择题：规则判断阶段的每种情况；只在两条以上没完成时才问在做哪条、有了上一版才问有没有变化；什么时候重写（没变化不写；阶段变、条目变、拿不准、在等你都写）；Jev 说不清阶段时退回规则；没有 Jev 时的兜底。
- 文字：写看板的请求（清单、阶段、是否在等你）、中英文、回复解析；没有模型时的固定句子（中文和英文）；条目读回。
- 开关：按项目存、换一个进程读回、文件权限 600、文件坏了当没设置。
- 终端小窗口的文字（μ 是希腊字母 U+03BC）。
- 通过 pi 的测试 harness：没打开的项目里一次都不看；`/board on` 之后干活中途看一次、停下时看一次，写看板的模型读到了步骤和代理的话、语言对，看板内容没进代理的消息；在等你时列出要你确认的问题、写看板的模型答非所问时用固定句子；Jev 说没变化时不调用写看板的模型；`/board off` 之后不再看。

做过变异检查：去掉“项目没打开就不看”、去掉“没变化不写”、去掉“停下时看一次”，都有用例失败。

未验证：真实 Jev 对这几道题的准确率；真实的会说人话的模型写出来的效果；桌面端面板。

# 目标模式（`/goal`）

更新日期：2026-09-22。状态：已完成并测试（harness）；桌面端还没有对应的界面，只有展示事件 `goal.state` 可用。

## 1. 要解决什么

长任务里最常见的失败不是做错，而是**停早了**：模型说一句“基本完成了”就收工，用户回来才发现测试没跑、验收条件还开着。pi 上游没有“目标模式”（查过：示例扩展里有 plan-mode、todo、handoff，没有自动续跑），Claude Code 的 `/goal` 是用一个 Stop hook 把会话拦住。mu 的做法是把“拦不拦”交给判定器，并且让**事实压过说法**。

## 2. 怎么用

| 命令 | 作用 |
| --- | --- |
| `/goal <条件>` | 定下目标并立刻开工。条件用你自己的话写，例如“packages/x 的测试全部通过，README 写明新开关” |
| `/goal` | 看当前目标和状态 |
| `/goal clear` | 取消（`off` / `stop` / `none` 同义） |

条件本身会像你的普通消息一样进入任务帧：writer 据此写出验收条件，这些条件就是 to-do 清单，也就是目标模式判断“做完没有”的事实依据。

## 3. 每次模型想停下来时发生什么

1. 你按了 Esc → 暂停（“你打断了运行”）。模型调用失败 → 暂停。这两种都不问判定器。
2. harness 先数事实：任务帧里没勾掉的验收条件有几条；这一轮改过文件之后有没有跑过任何命令。
3. 判定点 `goal.met` 问两个是非题（只读模型的结束语，不读全部历史）：
   - `achieved`：结束语是否表示目标已**完全**达成？
   - `needs_user`：结束语是否在向用户要一样“没有它就干不下去”的东西？
4. 策略（顺序即优先级）：
   - `needs_user` 确信为是 → **等你**。向用户提的问题，绝不能靠“继续干”来回答。
   - 有未勾的验收条件，或改完没跑过 → **继续**，不管结束语怎么说。
   - `achieved` 确信为是 → **达成**。否则（否、或拿不准）→ **继续**。
5. “继续”时给模型发一条 `kyrn.goal` 消息：目标原文、未完成的验收条件、未验证的文件、第几次续跑；并触发下一轮。

### 自己会停下来的五种情况

| 情况 | 说明 |
| --- | --- |
| 模型需要你 | 见上 |
| 你打断 / 模型调用失败 | 不会顶着错误空转 |
| 连续空转 | 连续 `idleLimit`（默认 2）轮一个工具都没调用就结束：它在原地打转 |
| 续跑次数用完 | `maxContinuations`，默认 20，从你上一次发言算起 |
| 时间用完 | `maxMinutes`，默认 180，从你上一次发言算起 |

暂停之后，**你发的下一条消息就是“接着干”**：目标恢复，额度重新计。重新打开会话时，原来在跑的目标以“暂停”状态回来，不会自己启动（你可能已经不在电脑前）。

## 4. 没有判定器时

`goal.met` 在 `off`、`shadow`、判定器不可用、或判定层级不具备 `relate` 能力（本地 Laya）时走兜底规则：**只认事实**。有未勾的验收条件或未验证的改动 → 继续；否则 → 暂停并说明“没有判定器能读出目标是否达成，也没有可以证明未完成的事”，由你定。所以没有 Jev 的用户也能用目标模式，只是它不会替你读结束语。

## 5. 与其它功能的关系

- **完成核对**（`turn.completion`）：目标在跑时它让位，因为目标模式带着同样的事实发同一类提醒，两个声音没有意义。目标不在跑时一切照旧。
- **任务帧 / to-do**：验收条件是目标模式的事实来源。没开任务帧时 `openItems` 恒为 0，只剩“改完没跑”这一条事实和判定器的读法。
- **硬约束把关**：照常生效。续跑不会绕过你的约束。
- **会话树**：状态存成 `kyrn.goal` 条目，回退或分叉之后恢复的是那个分支上的目标。

## 6. 验证情况

已验证（`test/goal.test.ts`，7 个用例，faux 模型 + `MockJudgeProvider`）：策略的每一条分支与兜底；未达成 → 续跑 → 达成的完整序列与条目；连续空转自停；模型提问时暂停、用户回答后恢复并达成；续跑额度；`shadow` 下只认事实、且完成核对不再重复提醒；`/goal`、`/goal clear`、条目解析。做过变异检查：去掉“等你”分支和空转保护，对应用例会失败。

未验证：真实 Jev 对 `achieved` / `needs_user` 两个问题的校准（阈值沿用 `threeZone` 默认值）；真实长任务里 20 次额度是否合适；打断（Esc）路径只有代码，没有自动化用例；桌面端界面。
